Java 程序的结构与编译运行模型

你会 Python 和 TypeScript,通用编程概念(变量、函数、类、类型)不用重新学。 这一课只讲一件 Java 特有、Python 和 TS 都没有的事情: Java 源代码在能运行之前,必须先被编译成字节码,而且文件、类、方法的命名有硬性规则。

1. 三种语言的运行方式对比

为什么 Java 要这么设计?
Java 从一开始就是为"编译一次,到处运行"设计的:javac 把源码编译成与平台无关的字节码(.class 文件), 真正执行字节码的是 JVM(Java Virtual Machine)。文件名必须匹配 public 类名,是为了让编译器和工具能在不打开文件内容的情况下, 就知道"这个文件里应该有哪个 public 类"——这在大型项目里对构建工具、类加载器都很重要。

2. 一个最小的 Java 程序长什么样

public class Greeting {
    public static void main(String[] args) {
        System.out.println("Hello, Java");
    }
}

逐个拆解这几个词:

  • public class Greeting — 声明一个名叫 Greeting 的类,public 表示这个类对其他包可见。这个文件必须叫 Greeting.java。
  • public static void main(String[] args) — 这是 JVM 认识的固定入口签名。
    • public:JVM 要能从外部调用它。
    • static:不需要先创建一个 Greeting 对象就能调用——JVM 启动时还没有任何对象实例。
    • void:这个方法不返回值。
    • String[] args:命令行参数数组,类似 Node.js 里的 process.argv。
  • System.out.println(...) — 标准输出打印,相当于 Python 的 print()、TS/JS 的 console.log()。

3. 编译和运行是两个独立的命令

javac Greeting.java   # 编译:生成 Greeting.class(字节码)
java Greeting          # 运行:注意不加 .class 后缀,交给 JVM 执行
类比 TypeScript: javac 大致对应 tsc,java 大致对应 node。 区别是 TypeScript 编译产物是给 Node/浏览器读的 JS 源码,Java 编译产物是给 JVM 读的字节码,人类不会直接去读 .class 文件。
