包装类与自动装箱/拆箱

上节课留了一个口子:ArrayList 不能装 int,只能装 Integer,但 int first = scores.get(0) 又能正常跑——Java 到底在背后做了什么? 这节课就回答这个问题。

1. 为什么要有包装类

Java 的类型系统分两种:

  • 基本类型:int、double、boolean、char 等——存值,不是对象,不能放进 List
  • 引用类型:所有的类、接口、数组——是对象,可以放进 List

包装类就是给每个基本类型配一个对应的引用类型:

基本类型包装类
byteByte
shortShort

longLong

doubleDouble

booleanBoolean
记忆:除了 int → Integer 和 char → Character 是全称外,其余都是首字母大写的原名。这两个特殊的是因为 Int/Char 作为类名历史上被占用了。

2. 自动装箱与自动拆箱

// 装箱(boxing):基本类型 → 包装对象
Integer boxed = 42;                // 等价于 Integer boxed = Integer.valueOf(42);

// 拆箱(unboxing):包装对象 → 基本类型
int unboxed = boxed;              // 等价于 int unboxed = boxed.intValue();

// 在 ArrayList 里实际发生了什么
List<Integer> list = new ArrayList<>();
list.add(85);                     // 装箱:85(int)→Integer.valueOf(85)
int score = list.get(0);          // 拆箱:list.get(0)(Integer)→Integer.intValue()
score = score + 10;               // 拆箱做加法,结果还是 int
Java 装箱/拆箱PythonTypeScript
有这个区分吗 有,int 和 Integer 是不同的东西 没有——int 本身就是对象,Python 里一切皆对象 没有——number 既是基本类型也是对象,引擎自动处理
自动装箱/拆箱是编译器的"语法糖":你在源码里写 Integer x = 5,编译后字节码里实际是 Integer.valueOf(5)。 不是你代码运行到这一行时才"慢慢变成"对象——编译期就已经把转换代码塞进去了。

3. 容易踩的坑

坑 1:null 拆箱会炸

Integer maybeNull = null;
int value = maybeNull;   // 运行时 NullPointerException!拆箱等价于 maybeNull.intValue(),对 null 调方法当然炸

坑 2:== 比较的是引用,不是值

Integer a = 127;
Integer b = 127;
System.out.println(a == b);   // true(小值被缓存了,指向同一个对象)

Integer x = 200;
Integer y = 200;
System.out.println(x == y);   // false(超出缓存范围,是两个不同的对象)
Integer 缓存:Java 把 -128 到 127 的 Integer 对象预先创建好并缓存(Integer.valueOf() 会优先从缓存取)。 所以小值用 == 偶尔能撞对,大值一定错。比较 Integer 的值请用 .equals() 或者拆箱成 int 后再 ==。

预测一下:这段代码输出什么?

Integer x = 100;
Integer y = 100;
Integer a = 300;
Integer b = 300;

System.out.println(x == y);
System.out.println(a == b);
System.out.println(x.equals(y));
System.out.println(a.equals(b));

false
true
true

x == y:100 在 -128~127 缓存范围内,两次装箱拿到同一个对象,用 == 比较引用地址 → true。
a == b:300 超出缓存范围,每次装箱创建一个新对象,两个对象地址不同 → false。
x.equals(y) 和 a.equals(b):equals() 比较的是值,所以不管缓存不缓存都是 true。
