集合类型:Map / HashMap

前面的 ArrayList 靠下标定位元素——要么按顺序遍历,要么记住下标。但很多后端场景是"给一个键,查对应的值": 用户名查角色、courseId 查课程名、token 查会话。这种场景该用 Map——键值对集合,HashMap 是最常用的实现。 概念上和 Python 的 dict、TypeScript 的 Record/Map 是一回事。

1. 声明与基本操作

import java.util.Map;
import java.util.HashMap;

Map<String, Integer> scores = new HashMap<>();
scores.put("Alice", 90);          // 新增/更新一个键值对
scores.put("Bob", 85);
scores.put("Alice", 95);          // 键已存在 → 覆盖旧值,不是新增

System.out.println(scores.get("Alice"));        // 95
System.out.println(scores.get("Zoe"));           // null,键不存在
System.out.println(scores.containsKey("Bob"));   // true
System.out.println(scores.size());               // 2,注意不是 put 调用次数
scores.remove("Bob");                             // 按键删除
和 List 一样,声明用接口类型: Map<K, V> m = new HashMap<>(),Map 是接口,HashMap 是实现类。 <String, Integer> 是两个泛型参数,第一个是键的类型,第二个是值的类型。

get 查不到键会返回 null,不会报错: 如果值类型是 Integer 这种包装类, 拿到 null 后马上当 int 用(自动拆箱)就会炸——这和第 7 课讲的 ArrayList<Integer> 拆箱 NPE 是同一个坑, Map 里更容易踩,因为"键不存在"太常见了。安全写法是先 containsKey 判断,或者用下面的 getOrDefault。

2. 遍历

Map<String, Integer> scores = new HashMap<>();
scores.put("Alice", 90);
scores.put("Bob", 85);

// 最常用:entrySet(),一次拿到键和值
for (Map.Entry<String, Integer> entry : scores.entrySet()) {
    System.out.println(entry.getKey() + ": " + entry.getValue());
}

// 只要键,或只要值
for (String name : scores.keySet()) { ... }
for (int score : scores.values()) { ... }

// 查不到就用默认值,不用先 containsKey 再 get
int score = scores.getOrDefault("Zoe", 0);   // 0
HashMap 不保证顺序: 遍历 entrySet() 的顺序和 put 的顺序不一定一致,也不是字典序——这是 HashMap 底层哈希表结构决定的。 如果需要保留插入顺序或排序,有 LinkedHashMap/TreeMap,先知道存在,不展开。

预测一下:这段代码输出什么?

Map<String, Integer> scores = new HashMap<>();
scores.put("Alice", 90);
scores.put("Bob", 85);
scores.put("Alice", 95);
System.out.println(scores.get("Alice"));
System.out.println(scores.size());
先自己想,想好了再展开看答案

输出 95 和 2。第二次 put("Alice", 95) 的键和第一次相同,不是新增一条记录,而是把 "Alice" 对应的值从 90 覆盖成 95。 所以 size() 数的是唯一键的个数(2:Alice、Bob),不是 put 被调用的次数(3次)。
