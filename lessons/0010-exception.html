异常处理:try-catch

从第 1 课到现在，你的程序已经炸过很多次了：数组越界 ArrayIndexOutOfBoundsException、null 拆箱 NullPointerException。 这些"炸掉"在 Java 里叫异常(Exception)——程序运行时出了问题，JVM 抛出一个异常对象，如果没人接住，程序直接终止。 try-catch 就是来接住异常的机制。

1. 基本语法

try {
    // 可能出异常的代码
    int result = 10 / 0;
    System.out.println("这行不会执行");
} catch (ArithmeticException e) {
    // 接住异常后的处理代码
    System.out.println("除零错误: " + e.getMessage());
}
System.out.println("程序继续运行");  // ← 这行会执行！

2. 你见过哪些异常?

异常类型什么时候出现你在哪课碰到的
ArrayIndexOutOfBoundsException 数组下标越界 第 5 课
NullPointerException 对 null 调方法/属性(含 null 拆箱) 第 7、9 课
ArithmeticException 整数除零 还没碰到
NumberFormatException 字符串转数字失败,如 Integer.parseInt("abc") 还没碰到

这些都是 RuntimeException 的子类——不强制要求处理，你可以不写 try-catch，程序炸了就炸了。但业务代码里你显然不想让一个异常直接把整个请求打挂。

3. 多重 catch 与 finally

try {
    String input = "abc";
    int num = Integer.parseInt(input);     // NumberFormatException
    int result = 100 / num;                // 如果 num==0 → ArithmeticException
} catch (NumberFormatException e) {
    System.out.println("输入不是数字");
} catch (ArithmeticException e) {
    System.out.println("不能除零");
} catch (Exception e) {
    System.out.println("其他未知异常: " + e.getMessage());
} finally {
    System.out.println("这行无论如何都会执行");
}
catch 的顺序有讲究: 从上到下匹配，匹配到第一个就停。Exception 是所有异常的父类，放在最上面会吞掉所有具体的 catch——所以 先抓具体，最后抓宽泛。 finally 块可选，无论是否抛异常、异常是否被 catch，它都会执行。通常用来释放资源（关文件、关数据库连接）。

4. 什么时候用 try-catch，什么时候不管?

做法适用场景
用 try-catch 包住并处理 你知道可能出错，而且有办法补救。比如用户输入了"abc"但你想要的是数字——可以 catch 后给个默认值或提示重新输入
不 catch，让异常往上抛 出了这个错说明程序进入了不可预期的状态，你也不知道怎么补救。比如内部数据结构的 NPE——更可能是代码 bug，不是该 catch 的问题
catch 后记录日志再抛 需要记录错误信息用于排查，但自己处理不了，交给上层处理
一个简单原则: 能正确处理异常时才 catch，否则别碰它。 新手常见错误是 try { ... } catch (Exception e) {}——空的 catch 块，把异常吞掉当没发生。这比程序直接炸掉更危险，因为你不知道出了问题。

预测一下:这段代码输出什么?

int[] arr = {10, 20, 30};
try {
    System.out.println(arr[5]);
    System.out.println("A");
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("B");
}
System.out.println("C");
先自己想,想好了再展开看答案

输出 B 然后 C。arr[5] 抛异常 → try 块里后面的 "A" 跳过 → 跳到 catch 打印 "B" → catch 结束后程序继续，打印 "C"。

关键: catch 不会让程序终止，这只是"异常被处理了"。如果你把 catch 删掉，程序直接炸在 arr[5] 那一行，C 也不会打印。
